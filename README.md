About the project

Students report problems such as WiFi, water, electricity, classroom and hostel issues verbally or on paper, so there is no record of them. This project is a simple REST API with a database that stores and manages these complaints. It supports all four CRUD operations, uses JSON, and is tested with Postman. A small website uses the same API.

Technologies
Node.js and Express.js (REST API)
SQLite (database, file complaints.db, created automatically)
HTML, CSS and JavaScript (website)
Postman and Newman (API testing)
How to run
npm install
npm start
API: http://localhost:3000/api/complaints
Website: http://localhost:3000

To run the Postman collection from the terminal (the server must be running):

npm run test:api
Entity: Complaint
Field	Description
id	Unique ID (generated by the database)
studentName	Full name, every word starts with a capital letter, e.g. Saira Abbas
rollNo	Capital letters only, e.g. K22SW006
category	Type of problem, e.g. WiFi / Internet, Water, Electricity
description	Details of the problem
status	Pending (default), In Progress or Resolved
API endpoints

Base URL: http://localhost:3000/api/complaints

Operation	Method	URL	Success	Errors
Create	POST	/api/complaints	201 Created	400
Read all	GET	/api/complaints	200 OK	
Read one	GET	/api/complaints/:id	200 OK	404
Update	PUT	/api/complaints/:id	200 OK	400, 404
Delete	DELETE	/api/complaints/:id	200 OK	404

Example request body (POST and PUT):

json
{
  "studentName": "Saira Abbas",
  "rollNo": "K22SW006",
  "category": "WiFi / Internet",
  "description": "WiFi is not working in the Software Engineering department.",
  "status": "Pending"
}
Postman tests

Import postman/Complaint_API.postman_collection.json into Postman. It has 17 test cases:

TC01–TC04: add, get all, get one, update a complaint
TC05–TC08: missing fields and non-existent IDs (400 / 404)
TC09–TC10: delete a complaint and confirm it cannot be retrieved (404)
TC11–TC14: wrong ID, invalid name, invalid roll number and invalid status
TC15–TC17: add Water, Electricity and Classroom complaints (these stay in the database)
Website

Open http://localhost:3000. Sign in with your name and roll number (correct input turns green, wrong input turns red). The portal has a Dashboard, Register Complaint, All Complaints (view, edit, mark resolved, delete, search) and Recent Activity.

Validation and security
Server and website use the same rules for name, roll number and status.
Prepared SQL statements (no SQL injection) and escaped output on the website.
Request size limit, rate limit, CORS limited to local pages, security headers and generic error messages.
